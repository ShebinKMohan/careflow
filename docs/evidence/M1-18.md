## Implemented acceptance criteria

- `eval` is a locked uv workspace package with the `careflow-eval` argparse entry point.
  Commands: `list`, `validate`, `generate`, `run`, and an explicit `review` gate.
- The JSON Schema and typed loader require synthetic inputs, provenance and content-bound
  independent automated review. Named simulator values contribute to the reviewed hash.
- The authored 50-case mix is 8 chest, 6 stroke, 8 sepsis, 6 child, 4 breathing and 18 routine.
  Pre-review validation passed with zero schema, provenance or rule inconsistencies. The
  pre-review hash is `f8021026ce4f25c2783f0a10b7b0b2592c3a99e80e3b69a4e660203f76fe9be5`.
  There are 277 expected fact slots and 25 expected alerts across six rule IDs. The gold
  completeness audit preceded any extraction baseline; see `datasets/REVIEW.md`.
- The registry implements deterministic field precision/recall/F1, alert recall and benign
  false-alert rate, incomplete/dropped-fact rates and p50/p95 latency. Hand-calculated tests
  include wrong-value FP+FN, duplicate matching and exact numeric tolerance boundaries.
- The rules suite invokes the real rules engine on all 56 existing cases. The extraction
  suite invokes the production extractor and rules on its actual output plus supplied
  context. Expected labels enter scoring only.
- Recording uses the canonical `ReplayProvider`. Case receipts bind input/prompt/rules/model,
  output and duration. Missing or changed evidence fails replay; historical latency is
  separate from replay execution time. Failed final model-identity verification cannot be
  replayed later as an attributed successful batch.
- JSON/Markdown reports include current and recorded source provenance, dataset identity,
  model receipt, prompt/ruleset versions, per-key/per-rule results and failed scenario IDs.
  Every suite has independent timestamped artifacts and `LATEST.md`.

`child-parent-unsure-waking` first returned invalid null-valued fields, then its structured
correction exceeded the 20-second total timeout. The production incomplete outcome is
preserved, including the missed `NG143_RED_FLAG`: that rule's observed recall is 3/4.

claim. Every scenario has at least one field mismatch under the fixed strict normalization;
per-key and per-case data remain visible. Expected labels, normalization, production prompts
and the timeout were not tuned after observing these results.

A read-only error audit accounts exactly for all 47 false-positive and 86 false-negative
field slots. This breakdown explains the fixed score; it does not rescore the baseline.

For the 13 absent `pain_present` fields, pain scores were still correctly extracted. The
contract permits the generic pain flag, but the prompt does not explicitly require expanding
a numeric pain score into both fields. The live tap path also writes only the selected key;
question selection infers pain from the score without materializing another fact. Therefore
these are representation-policy gaps, not 13 failures to recognize pain. Make that mapping
explicit before any future training or evaluation change. Triage features read the generic
flag independently, so it warrants a downstream check.

All 13 omitted symptom strings survive as chief-complaint text, so the patient narrative was
preserved while the extra structured representation was absent. The prompt has a dual-field
example; the overlapping elbow-tenderness case also merits an explicit annotation-policy note.
Keep the reviewed corpus fixed, prioritize uncertainty and timeout handling, and publish any
future prompt or normalization version with a fresh comparison rather than revising this run.

These are whole scripted-transcript extraction measurements, not per-turn UI, nurse-alert
or complete journey timings. They do not establish the 1,000 ms full alert-delivery target.
The corpus and automated reviews are synthetic evidence, not clinical validation.

The rules-only baseline `eval/reports/rules/20260927-095225.json` evaluates the real engine
on all 56 existing rule scenarios: recall 1.0, false-alert rate 0.0. Its exact replay already
matched all metrics, including historical timings. Rules execution alone is not the measured
patient-input-to-alert latency.

## Exact replay of the live baseline, 27 September 2026

Review of the timeout-event replay: canonical replay still serves every recorded reply
through `ReplayProvider`. Only a receipt that proves the production deadline raises
`TimeoutError` into the real extractor, at the recorded call. The proof is `failure_code:
timeout`, the binding `timeout_seconds: 20.0`, a case duration of at least 20 s that contains
every call's timing, a final call recorded as `CancelledError`, recorded replies for every
earlier call, a bound partial cassette and the endpoint completion manifest. `structured()`
does not catch provider exceptions and `asyncio.wait_for` re-raises the provider's
`TimeoutError`, so the extractor takes the same `except TimeoutError` branch as the live
deadline did. The ordered request hashes, the call outcomes and the extraction/rules output
hash are then checked. Anything else stays `not_run` or fails hard.

With no model server listening on port 8081:

```sh
uv run careflow-eval run extraction_en --replay --output <scratch dir>
# Run status: completed (execution status, not a clinical pass)
# field_f1: 0.7417475728155339   alert_recall: 0.96   false_alert_rate: 0.0
# latency_p50_ms: 9113.418707973324   latency_p95_ms: 12284.610874950886
```

Compared field by field with the retained live JSON `eval/reports/extraction_en/20260927-095128.json`:
every metric (with its details) is equal, the same 50 case ids fail the strict per-case
quality flag, and no case differs in its prediction (facts, alerts, incomplete and dropped
counts, historical latency), output hash, error code, rule validation, field F1 or quality
flag. `child-parent-unsure-waking` is the only case replayed as `confirmed_timeout_event`;
the other 49 replay as `recorded_replies`. The live `LATEST.md` is unchanged; the replay
verification is written separately under `eval/reports/replay-verification/`.

CI coverage, in the existing `make test-py` collection:
