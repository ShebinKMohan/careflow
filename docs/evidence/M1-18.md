## Implemented acceptance criteria

- `eval` is a locked uv workspace package with the `careflow-eval` argparse entry point.
  Commands: `list`, `validate`, `generate`, `run`, and an explicit `review` gate.
- The JSON Schema and typed loader require synthetic inputs, provenance and content-bound
  independent automated review. Named simulator values contribute to the reviewed hash.
- The authored 50-case mix is 8 chest, 6 stroke, 8 sepsis, 6 child, 4 breathing and 18 routine.
  Pre-review validation passed with zero schema, provenance or rule inconsistencies. The
  pre-review hash is `f8021026ce4f25c2783f0a10b7b0b2592c3a99e80e3b69a4e660203f76fe9be5`.
  There are 277 expected fact slots and 25 expected alerts across six rule IDs. The gold
  completeness audit preceded any extraction baseline; see `datasets/REVIEW.md`.
- The registry implements deterministic field precision/recall/F1, alert recall and benign
  false-alert rate, incomplete/dropped-fact rates and p50/p95 latency. Hand-calculated tests
  include wrong-value FP+FN, duplicate matching and exact numeric tolerance boundaries.
- The rules suite invokes the real rules engine on all 56 existing cases. The extraction
  suite invokes the production extractor and rules on its actual output plus supplied
  context. Expected labels enter scoring only.
- Recording uses the canonical `ReplayProvider`. Case receipts bind input/prompt/rules/model,
  output and duration. Missing or changed evidence fails replay; historical latency is
  separate from replay execution time. Failed final model-identity verification cannot be
  replayed later as an attributed successful batch.
- JSON/Markdown reports include current and recorded source provenance, dataset identity,
  model receipt, prompt/ruleset versions, per-key/per-rule results and failed scenario IDs.
  Every suite has independent timestamped artifacts and `LATEST.md`.

## Actual local review observations

The local model was started exclusively through `scripts/with_llm.sh`, using the existing
public, ungated cached `mlx-community/Qwen3.5-9B-MLX-4bit` snapshot at
`938d8919941c6e7efd3c7150eff7fe9d12afa631`. No paid API was used. The writer identity is the
in-session coding agent, GPT-6. Review used local Qwen and the already authenticated
Claude subscription CLI, restricted to offline data review with tools and MCP disabled.

The server advertised both the pinned Qwen snapshot and its built-in SmolLM model ID. The
first attempt correctly refused to attribute the ambiguous `default_model` alias. Subsequent
calls explicitly selected the observed pinned Qwen snapshot path as `served_model`, with
matching endpoint probes and recorded launch evidence. The unrelated advertised model was
not used as the judge.

The first actual five-case review returned malformed JSON and exceeded the 120-second
batch limit during its structured correction. Zero approvals were published. The raw
response and timeout receipt are preserved in
`eval/datasets/review-receipts/20260927-090621-190254/`. The remaining run was interrupted
after that failed batch. A subsequent run requests concise valid JSON verdicts and uses a
300-second offline review limit; its four acceptance checks are unchanged. Full review
messages and their hash are now retained with each receipt.

The complete batched Qwen pass approved 24 and rejected 26. Fifteen failures substituted a
hash for the scenario ID; eleven objections contradicted the implemented rules or arithmetic.
Only those eleven cases' rationale text was clarified; patient turns, fact/alert gold,
vitals and levels stayed unchanged. The exact before/after audit is retained in
`datasets/M1-18-REVIEW-AUDIT-2026-09-27.json`. A single-case Qwen pass then reviewed eleven
more cases, approved five and repeated six incorrect objections before it was stopped.
Its five approvals were recovered into the audit log from their existing raw receipts and
byte-identical approved files; recovery metadata identifies each reconstruction. Logging
now flushes each completed batch so later interruption preserves those entries directly.

The offline Claude Sonnet 5 reviewer approved all 21 unresolved cases, with no further gold
changes. The CLI's principal model identity is bound to its reported token accounting;
auxiliary Haiku usage remains visible. Filtered authentication evidence confirms the existing
Claude subscription, and the child environment excludes API/cloud credentials. There were
**six subscription CLI invocations total: one identity probe and five review calls**.

`uv run careflow-eval validate intake_en` now admits **all 50 reviewed cases**, with zero
validation failures and SHA
`b8e3c26807e65a4d634c29bbb4fa783e78f5880eb22399c1bcd019e49d4f0bc9`.
Twenty-nine approvals are from local Qwen and twenty-one from Claude Sonnet 5. The observed
failures are retained; no approval was inferred from a malformed, mismatched or rejected
model reply.
