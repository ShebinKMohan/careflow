# M2-05: The consent gate and the ID-tap check-in mock, verified (SHE-296)

Status: 28 September 2026. ADR-036 built the consent gate and the mock ID tap; this is its test
phase (ADR-056). Research prototype; synthetic data only; not for clinical use.

## What the tests found, and the fixes

1. **A failed consent save was ignored.** The kiosk went to the intake whatever the API answered,
   and `hasConsent` read the unsaved choices. Now the choices count only after the API saved them
   (`markConsentSaved`). A failed save says "Your choices were not saved…" with **Try again** and
   **Start again**, and the kiosk stays on the check-in screen.
2. **Voice ignored data use on the servers.** The API's voice turns and the voice service read
   `voice` only; the kiosk also required `data_use`. All three now use `voice and data_use`
   (`careflow_api.consent.allows_voice`).
3. **The synthetic card number was in FHIR search URLs**, and so in httpx's INFO log line (and
   HAPI's access log). The FHIR client now searches with `POST [type]/_search`, parameters in a
   form body. Found by the log scan below.
4. **Check-in hung when the API was unreachable** ("Checking in…" until the idle wipe). The kiosk
   now says the clinic system cannot be reached and lets the patient try again; it is not counted
   as a failed attempt.
5. **`make up` could not start the voice service on Apple silicon** since M2-08: the voice process
   was given the RAG package's `embeddings` extra, which uv refused, and honcho stopped the stack.
6. **A second stack's voice service called the dev stack's API port** (it reads
   `CAREFLOW_API_BASE_URL`, which the stack env did not set). `scripts/stack.py` now writes it.

`make up` also turns the kiosk's microphone button on when it runs the voice service (an empty or
unset `NEXT_PUBLIC_VOICE_ENABLED`); the button still shows only after the saved voice consent.

| the kiosk taps only as itself, at its clinic | another clinic or kiosk 403; nurse, admin and patient tokens 403; no token 401; a malformed card 422, not echoed |

**The log scan.** Every test captures at INFO, and at DEBUG for CareFlow's own loggers. It fails on:
- an unmasked card number (`784-\d{4}-\d{7}-\d`);
- a JSON web token (`eyJ`);
- the test password or device secret;
- the session tokens;
- the patient's words.

SQLAlchemy's SQL echo stays at WARNING: it prints statement parameters by design and is a debugging switch, never on in a deployment.

## Not covered, and why

- **The voice journeys need Apple silicon.** (a) and the reload journey skip on a stack without a voice service. CI runs `VOICE=0`, so it skips them with that reason and runs (b), (c) and (d).
- **The server gates voice only.** A session without a record can still post typed answers to the API. The kiosk reaches the intake only with a saved record, and a data-use refusal never checks in (ADR-056).
- **An abandoned session remains.** A failed save followed by "Start again" leaves the session check-in opened, with no consent and no answers, until it expires.
