# Evidence: [M1-04] Prepare the KTAS dataset and train the baseline urgency models

- **Linear:** SHE-268. **Branch:** `she-268-ktas-baseline`.
- **Machine:** MacBook Pro M3 Pro, 18 GB. No Docker, no LLM, no GPU.
- **Code:** `services/triage` (`careflow_triage`):
  - `ktas/load.py`, `ktas/features.py`, `ktas/download.py`, `ktas/fixture.py`;
  - `splits.py`, `train.py`, `calibrate.py`, `metrics.py`, `report.py`;
  - `inference.py`, `scales.py`, `cli.py`;
  - configuration in `config/ktas_mapping.yaml` and `config/triage_scales.yaml`.
- **Decisions:** ADR-019.
- **Data:** Moon et al., PLOS ONE 2019 (doi:10.1371/journal.pone.0216972, CC BY 4.0), S1 Appendix. It has 1,267 records of adult patients in two Korean EDs, October 2016 to September 2017. The study facts were read from the article on 27 Sep 2026. How to get the data and the rules for handling it are in `services/triage/DATA.md`.
- **The data is never committed.** `services/triage/data/` and `services/triage/artifacts/` are git-ignored. The only committed outputs are:
  - the aggregate reports in `eval/reports/triage/` (`ktas_baseline_20260927.{json,md}` and `ktas_profile.md`);
  - the split row indices in `services/triage/splits/ktas_v1.json`;
  - `services/triage/MODEL_CARD.md`.

## 1. `train --model hgb` and `--model lr` finish in <2 min and write the artifact and report

```

ktas-lr-ebf31b5e-s42: macro-F1 0.705, under-triage L1-2 9/37, ECE 0.113 -> 0.153 (T=1.19) in 0.25 s

```

- The HGB time includes its 4-point validation grid and the 5-fold CV.
- Each run writes `artifacts/<model_version>/{model.joblib, background.npy, meta.json}`.
- `meta.json` holds:
  - the features, T and parameters, and the HGB grid;
  - the seed, the CSV's SHA-256 and the split file;
  - the metrics, the library versions and the Python version.
- Each run also rewrites `eval/reports/triage/ktas_baseline_20260927.{json,md}` for both models and `MODEL_CARD.md`.

## 2. The report shows per-level counts, under-triage L1-2 with CI, macro-F1, ECE before/after and the nurse comparator for both models

The split is 886 train, 190 validation and 191 test rows. Test counts per level (1-5) are 4, 33, 73, 69 and 12.

| Test set | Under-triage L1-2 (95% CI) | Over-triage | Macro-F1 | Accuracy | ECE before → after |
|---|---|---|---|---|---|
| hgb `ktas-hgb-ebf31b5e-s42` | 14/37 = 37.8% (24.1-53.9%) | 24/191 = 12.6% | 0.625 | 0.702 | 0.077 → 0.112 |
| lr `ktas-lr-ebf31b5e-s42` | 9/37 = 24.3% (13.4-40.1%) | 22/191 = 11.5% | 0.705 | 0.707 | 0.113 → 0.153 |
| nurses (`KTAS_RN`), same rows | 8/37 = 21.6% (11.4-37.2%) | 5/191 = 2.6% | 0.876 | 0.890 | n/a |

- **Nurses on all 1,267 rows:** under-triage 45/246 = 18.3% (14.0-23.6%), macro-F1 0.807.
- **5-fold CV.** Level 1 has only 4 test rows, so the report also gives a stratified 5-fold CV (pooled out-of-fold):

  | Model | Under-triage | Macro-F1 |
  |---|---|---|
  | lr | 80/246 = 32.5% | 0.554 ± 0.037 |
  | hgb | 104/246 = 42.3% | 0.586 ± 0.077 |

- **Calibration is reported honestly.** T is fitted on validation, where it lowers the error. On the test split, ECE rises for both models (see the table above), and ADR-019 explains why. HGB's validation ECE falls from 0.190 to 0.092.
- **No target is claimed as achieved.**
- **Other contents.** The report also has confusion matrices, the caveats (adults in two Korean EDs; nothing about children, UAE or UK patients) and the JSON twin.

## 4. `predict()` returns 3 reasons and a `model_version` in <20 ms per call

Timings were taken on the 191 real test rows after 5 warm-up calls, using `UrgencyModel.load(artifact).predict(facts)`:

| Model | p50 | p95 | Max |
|---|---|---|---|
| lr | 2.21 ms | 2.33 ms | 2.95 ms |
| hgb | 4.84 ms | 5.01 ms | 5.20 ms |

HGB takes a 20.1 ms median without `threadpool_limits(1)` (ADR-019).

Every call returned a contract-valid `UrgencySuggestion` with:

- the level, the scale and `display_label`;
- the calibrated confidence;
- 3 reasons that cite their fact ids;
- `model_version`.

`test_predict_returns_three_reasons_fast[lr|hgb]` asserts the same on the fixture, with every call under 20 ms.

The reasons are faithful to the model: `test_shap_values_add_up_to_each_class_logit[lr|hgb]` checks that the SHAP values plus the base value equal every class's logit. An example reason is "Heart rate 128/min made KTAS 2 more likely".

**Display labels** come from `config/triage_scales.yaml` ("display mapping; scales are not clinically equivalent"):

| Scale | Labels |
|---|---|
| KTAS | KTAS n |
| ESI | ESI n |
| CTAS | Resuscitation … Non-urgent |
| MTS | Red … Blue |

**Out-of-scope patients.** A recorded age under 15, in years or months, raises `OutOfScopeError` instead of giving a suggestion (`test_children_get_no_suggestion`). The data covers adults only.

## Deviations from the issue text

- **Data README location.** The issue asks for `services/triage/data/README.md`, but `git ls-files services/triage/data` must stay empty. So the committed doc is `services/triage/DATA.md`, and every `ktas download` copies it to `data/README.md` (git-ignored), which keeps the CC BY attribution with the rows.
- **Reason wording.** Reasons say "made KTAS k more/less likely", not "raised urgency". A SHAP value towards the predicted class shows which level a feature favours, not a change in urgency (ADR-019).
- **Contract additions** for three columns that had no M0-02 path, and for `display_label` (see above).
- **Adults only.** Beyond the issue, a known age under 15 gets `OutOfScopeError`, because the data is adults only.
- **Calibration.** T is fitted and stored as specified, but it raises test ECE for both models. This is reported, not hidden, and a follow-up is noted in ADR-019.
- **Default model.** `lr` is the default for the M1-05 port, because it under-triages less on test and in CV (ADR-019).
