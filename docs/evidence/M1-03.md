- **Parser edge cases:** garbage and non-ASCII bytes, partial lines (no newline), an empty line, unknown, repeated and missing fields, non-numbers, out-of-range values (HR 400, SpO2 101, 50 °C, HR −5), NaN and inf, CRLF, and an overlong frame are all rejected with `FrameError`. Empty fields are "not measured".
- **Deterministic output for a fixed seed:** seed 42 gives identical frames twice; seed 7 gives different frames.
- **Interpolation:** `septic` at 15 s is HR 122.0, SpO2 93.5, 39.35 °C, linear between the points; times before 0 and after the end clamp to the series.
- **BP only when both flags are on:** normal + `SIM_BP_CUFF=1` → BP; `SIM_BP_CUFF=0` or unset → no BP; `tachycardic_child` (no cuff) + `SIM_BP_CUFF=1` → no BP.
- **Scenario targets:** normal HR 78, SpO2 98, 36.8 °C; septic HR 118→126, SpO2 94→93, 39.2→39.5 °C; hypoxic HR 104, SpO2 90→88, 37.1 °C; tachycardic_child HR 165, SpO2 96, 38.9 °C. Cross-check against the M1-01 rules: the first septic reading plus a stated fever gives a partial NEWS2 ≥ 5 and `SEPSIS_NEWS2`.
- **LOINC codes** match `packages/contracts/fhir/mapping.yaml`: HR 8867-4, SpO2 2708-6 (59408-5 is the mapping's second coding), temperature 8310-5, SBP 8480-6, DBP 8462-4.

## 3. The dev endpoint returns 404 when `CAREFLOW_ENV` is not `dev`

`test_404_unless_the_env_is_dev[None|prod|test|DEV]`: unset, `prod`, `test` and `DEV` (case matters) all get 404 as `application/problem+json`, because the router is not registered. With `CAREFLOW_ENV=dev`: 202 `{"session_id": "ses_dev_1", "scenario": "hypoxic", "frames": 31, "simulated": true}`, and the background task stores the latest reading (SpO2 ≤ 89 at the end of hypoxic). The scenario comes from the body, then `VITALS_SCENARIO`, then `normal`; an unknown scenario is 422. No token → 401; a nurse token → 403.

## Deviations from the issue text

- **CLI token:** `kiosk_device`, not `patient_session`, because the contract gives `POST /v1/sessions/{id}/vitals` to the kiosk device only (contracts win).
- **Where the readings go:** the real vitals handler and status route are M1-12. Until then, the dev endpoint's simulator writes to an in-memory latest-reading store (dev only), and the kiosk panel is tested against the mock API.
- **SpO2 LOINC:** 2708-6 with 59408-5 as the second coding, as in the M0-04 mapping (the issue said 59408-5).
- **Where the panel lives:** `/vitals` hosts it (`?session=`, `?scenario=`); M1-13 moves it into the check-in flow.
- **Errors:** routing errors (unknown route 404, wrong method 405) are now RFC 9457 problem documents (`problems.py` handles Starlette's `HTTPException`). A new DB-free test covers this.
