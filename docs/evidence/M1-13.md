## 3. Idle: `page.clock.install()`, then `fastForward("01:20")`, returns to `/`; the keypad is empty and no session data is stored

`idle.spec.ts` checks in and then advances the clock by 80 s: 60 s idle, then the 15 s countdown.

- The kiosk is back on `/`, on the "Welcome" screen.
- **Back to `/intake` without a reload** (browser back, and a marker set on `window` beforehand is still there): the page shows "Please check in first.". The patient is gone from memory, not just off screen.
- **Tapping "English" again** shows an empty keypad.
- **Storage:** `localStorage` is empty. `sessionStorage` holds only `careflow.kiosk.device`, the kiosk's own sign-in (below). No stored value contains the session id, the session token or the initials.

The second idle test shows the "Are you still there?" dialog at 60 s with its countdown; "I'm still here" keeps the session on `/intake`.

**Mutation checks:**

- **Patient stored in `sessionStorage`.** Writing the patient to `sessionStorage` at check-in fails the happy path and the 80 s test, both at the storage assertion:

  ```
  Error: expect(received).toEqual(expected)
  +   "careflow.kiosk.patient",
  ```

- **No wipe.** With the wipe removed from both the idle timeout and the welcome screen, the 80 s test fails: going back shows the old question instead of "Please check in first.".
- **Idle wipe only.** Removing only the idle timeout's wipe leaves the test passing, because the welcome screen wipes as well (defence in depth).

## Accessibility (issue step 9)

- **Touch targets.** The happy path measures the smallest side of every button on each screen:

  ```
  smallest button side in px: {"keypad":64,"complaints":64,"severity":58.2}
  ```

  The first screenshot showed the 0–10 buttons at about 54 px wide, with "10" overflowing. The scale now uses an 11-column grid with no side padding at kiosk width (4 or 6 columns on narrow screens), so every button measures at least 56 px each way.
- **Focus.** The visible focus ring comes from `@careflow/ui` (a 4 px outline on `:focus-visible`).
- **Language.** `<html lang>` follows the chosen language (`en`; `ar` with `dir="rtl"`, as in the smoke test).
- **Colour.** Errors, the notice and the idle warning are all text; nothing depends on colour alone.
- **Contrast.** The tokens are the M0-08 high-contrast palette.

## Deviations from the issue text

- **Input modes** use the contract's `input_mode: tap | text | voice`, which the issue calls `source: tap | typed | voice`.
- **Contract addition.** The issue says to go to vitals "when `next_question` is `null`", but M0-03's responses had no `next_question`, and no question key to choose tap answers from. `IntakeQuestion` adds both, optionally. The kiosk falls back to `assistant_text` and `done` when they are absent (ADR-027). M1-12 fills them.
- **Device sign-in in `sessionStorage`.** The kiosk's own `kiosk_device` sign-in is kept in the tab's `sessionStorage` (as since M0-08), so a reload does not need staff. It is not patient data, and the idle test checks that it holds nothing about the patient.
- **Tap answers** send their label in the session language ("Chest pain", "8"): the turn API takes text.
- **Removed from the old check-in page:** the "Session id" display and the welcome card. The patient only needs the next question.
- **Arabic strings** for the new screens are machine-written and not reviewed by a native speaker (RTL is M2-01).
