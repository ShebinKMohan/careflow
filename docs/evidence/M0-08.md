## 4. Companion PWA: manifest, active service worker, API never served from cache

`apps/companion/tests/e2e/smoke.spec.ts`, against the production build:

- `GET /manifest.webmanifest` → 200: name "CareFlow companion", `display: standalone`, `start_url: /`, and icons 192x192 and 512x512. Each icon URL returns 200 `image/png`.
- `await navigator.serviceWorker.ready` → the active worker reaches state `activated`. After a reload the page is controlled (`navigator.serviceWorker.controller !== null`).
- After the QR claim, the `GET /v1/companion/status` response is 200 and `response.fromServiceWorker()` is `false`.
- Cache Storage holds only same-origin shell URLs: none under `/v1/`, none from another origin, and not `/status`.
- Screenshot: `docs/evidence/M0-08/companion-status.png`. Screenshots wait for `document.fonts.ready`, and two runs produced identical files.

`public/sw.js` precaches `/`, the manifest and the icons, and serves hashed `/_next/static/` assets cache-first. Every other request passes through untouched (network-only): other origins (the API), `/v1/`, RSC requests and other pages. The worker is registered in production builds only.

## 6. No API response is typed `any`

- `strict: true` is set in every `tsconfig.json` (apps, `packages/ui`; the base config has it too).
- `packages/contracts/ts-tests/client.test.ts` asserts `expectTypeOf(data).not.toBeAny()` and the exact `Schema<"Worklist">`/`Schema<"CheckinResult">` types for `createCareflowClient` calls. Mutation check: casting the response to `any` makes `tsc` fail with `TS2349 ... Inverted<ExpectAny<any>>`.
- `@typescript-eslint/no-explicit-any` is an error in the apps (a probe file confirmed it fires).
- All API types come from `@careflow/contracts`; none are hand-written.

## Deviations from the issue text

- **Playwright uses the installed Google Chrome** (`channel: "chrome"`, Chrome 153.0.8010.53). `playwright install chromium` fails because `cdn.playwright.dev` (Azure Front Door) times out from this machine, while GitHub, npm and Google Fonts respond. `PLAYWRIGHT_CHANNEL=chromium` switches to Playwright's own browser where it can be downloaded.
- **One Prism per app in e2e** (4010/4011/4012) instead of a shared 4010, so `pnpm -r test:e2e` can run in parallel. `make mock` and the apps' default base URL stay on 4010.
- **Stub sign-in screens**, since every route except login, device-token and QR claim needs a bearer token (Prism answers 401 without one): kiosk `/setup` (device token) and staff `/login`. Real flows come in M1-13, M1-15 and M2-06.
- **ESLint 10 with `settings.react.version: "19.2"`**: eslint-plugin-react's version detection calls `context.getFilename()`, which ESLint 10 removed. pnpm warns that eslint-plugin-react, eslint-plugin-import and eslint-plugin-jsx-a11y declare peers only up to ESLint 9.
- **React 19.2.8**, the version create-next-app 16.3.6 pins (19.3.0 exists). **`@types/node` 24.13.6** instead of 24.19.0, which was under a day old and failed pnpm's minimum-release-age check.
- **Prism's transitive advisories:** overrides move postman-collection's lodash (4.18.1) and uuid (11.1.1). The @faker-js/faker 5.5.3 advisory GHSA-qxc2-j82w-r537 is ignored in `osv-scanner.toml` until 2027-03-31. The fix (faker 10) breaks postman-collection at load, and the vulnerable `helpers.fake()` path is only reached when resolving Postman collections, which the mock never does (ADR-015).
- Install scripts are off (`allowBuilds: false`) for sharp, unrs-resolver, @swc/core, @parcel/watcher and @scarf/scarf (telemetry).
- `agentRules: false` in each `next.config.ts`: under an AI agent, `next dev` otherwise writes `AGENTS.md`/`CLAUDE.md` into the app.
- `pnpm -r lint typecheck test` is not a single pnpm command; it ran as `pnpm -r lint && pnpm -r typecheck && pnpm -r test`.
- The Arabic strings were written in-session and have had no native-speaker review. The back-translation check comes with M2-01. The README says "Arabic supported; not validated by native speakers".
