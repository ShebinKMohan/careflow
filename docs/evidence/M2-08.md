# M2-08: the clinic knowledge base, verified (SHE-304)

Status: 27 September 2026. ADR-039 built it; this is its test phase (ADR-053). Research prototype;
the handbook is fictional; no patient data.

## The table (`alembic upgrade head`, then `\d rag_chunks`)

Taken from a throwaway database migrated to head by the API's Alembic scripts
(`careflow_rag.scratch`, on the isolated test stack):

```text
                               Table "public.rag_chunks"
      Column      |           Type           | Collation | Nullable |      Default      
------------------+--------------------------+-----------+----------+-------------------
 id               | uuid                     |           | not null | gen_random_uuid()
 clinic_id        | uuid                     |           | not null | 
 section_id       | text                     |           | not null | 
 chunk_no         | integer                  |           | not null | 
 lang             | text                     |           | not null | 
 title            | text                     |           | not null | 
 body             | text                     |           | not null | 
 embedding        | vector(1024)             |           | not null | 
 content_sha256   | text                     |           | not null | 
 handbook_version | text                     |           | not null | 
 created_at       | timestamp with time zone |           | not null | now()
Indexes:
    "rag_chunks_pkey" PRIMARY KEY, btree (id)
    "ix_rag_chunks_clinic_id" btree (clinic_id)
    "rag_bm25_ar" bm25 (body) WITH (text_config=arabic) WHERE lang = 'ar'::text
    "rag_bm25_en" bm25 (body) WITH (text_config=english) WHERE lang = 'en'::text
    "rag_chunks_clinic_id_section_id_chunk_no_lang_key" UNIQUE CONSTRAINT, btree (clinic_id, section_id, chunk_no, lang)
    "rag_chunks_embedding_hnsw" hnsw (embedding vector_cosine_ops)
Check constraints:
    "rag_chunks_chunk_no_check" CHECK (chunk_no >= 0)
    "rag_chunks_lang_check" CHECK (lang = ANY (ARRAY['en'::text, 'ar'::text]))
    "rag_chunks_section_id_check" CHECK (char_length(section_id) <= 120)
Foreign-key constraints:
    "rag_chunks_clinic_id_fkey" FOREIGN KEY (clinic_id) REFERENCES clinic(id)
Policies (forced row security enabled):
    POLICY "clinic_isolation"
      USING ((clinic_id = (NULLIF(current_setting('app.clinic_id'::text, true), ''::text))::uuid))
      WITH CHECK ((clinic_id = (NULLIF(current_setting('app.clinic_id'::text, true), ''::text))::uuid))
```

The extensions: pgvector 0.8.6 and pg_textsearch 1.4.0. The BM25 mode is real BM25; the FTS
fallback was not needed.

## The automated review (`handbook/REVIEW.md`)

8 of 8 files passed, reviewed by `agent:local/qwen3.5-9b-4bit`
(`mlx-community/Qwen3.5-9B-MLX-4bit@938d8919941c6e7efd3c7150eff7fe9d12afa631`). The handbook was
written by `agent:claude-code/claude-opus-5-5`, so a different model judged it.

- **Structure and denylist.** Clean in every file.
- **Back-translation.** All 25 Arabic sections passed M2-01's check (`same_meaning` true); chrF
  was 42.8 to 91.6, against a floor of 40.
- **The judge.** It found every file fictional only and practical only, and every Arabic file
  saying what the English says, with no issue noted.
- **Records.** `eval/reports/rag_handbook_review.json`; REVIEW.md's log.

This is a machine review of a fictional handbook. It checks the Arabic against the English, not
the content against a real clinic (services/rag/README.md).

## The retrieval eval (`eval/reports/rag_retrieval.md`)

Measured on the reference machine:
- **Embedder.** Qwen3-Embedding-0.6B@97b0c614 on MPS (sentence-transformers 5.7.0, transformers
  5.17.0, torch 2.14.0).
- **Handbook.** Version `cdbc0b73e771d50b`: 25 sections per language, 50 chunks.
- **Questions.** 30 English and 30 Arabic answerable ones, plus 10 out of scope
  (`eval/datasets/rag/retrieval.jsonl`, sha256 `371708d0…`). They were written by the agent and
  held out; they are not real users'.

| Language | Mode | hit@5 | hit@1 | MRR | Missed at 5 |
| --- | --- | --- | --- | --- | --- |
| English | dense | 1.000 | 0.933 | 0.967 | none |
| English | bm25 | 0.800 | 0.433 | 0.586 | 6 |
| English | hybrid | 0.967 | 0.800 | 0.877 | `en-29` ("Is there a play area for kids?") |
| Arabic | dense | 1.000 | 0.867 | 0.922 | none |
| Arabic | bm25 | 0.933 | 0.567 | 0.719 | 2 |
| Arabic | hybrid | 1.000 | 0.867 | 0.917 | none |

- **The target** (hybrid hit@5 >= 0.90 in both languages) is met on these questions; it is a
  target, not a claim.
- **Dense is best here, published as measured** (ADR-053).
- **Speed.** A dense or hybrid question took about 33 to 35 ms (median, with the embedding); BM25
  about 2 ms. Measured, not a gate.

The best chunk's dense cosine, for M2-09's "I don't know" threshold:

| Language | Top-1 hits | Top-1 misses | Out of scope |
| --- | --- | --- | --- |
| English | 28: 0.370 to 0.794 (median 0.586) | 2: 0.367 to 0.406 | 5: 0.175 to 0.253 |
| Arabic | 26: 0.412 to 0.848 (median 0.636) | 4: 0.351 to 0.547 | 5: 0.193 to 0.347 |

The provisional `min_score: 0.45` (`config/rag.yaml`) would answer "I don't know" to 9 of the 60
answerable questions:
- English: `en-03`, `en-04`, `en-13`, `en-17`, `en-30`;
- Arabic: `ar-03`, `ar-13`, `ar-17`, `ar-30`.

It would refuse all 10 out-of-scope ones. The Arabic gap between the two groups is small (0.347
out of scope, 0.351 answerable). Revisiting the threshold is SHE-306's (M2-09); the distribution
is handed to it.
