## Mutation checks

Each change was made alone and reverted afterwards.

| Change | Result |
|---|---|
| no Enter guard on "Confirm level N" | the Enter test fails |
| polling disabled while paused | the paused test fails |
| a pushed alert does not load its session's facts | the banner test fails (no evidence) |
| any override counts as having a reason | the override test fails |
| both double-tap guards removed from "ECG done" | the ECG test fails (two requests) |

With only the handler guard removed, the ECG test still passes: the disabled button is the second guard.

## Accessibility and safety

- **Touch targets** are at least 64 px high (`min-h-touch`).
- **Colour is never the only signal:** severity, the rule and "Suggested"/"Confirmed" are written out.
- **Banners are silent regions,** with no live announcement and no sound.
- **Alerts always come first,** above the suggestion (safety rule 1).
- **Levels:** a level shows as "Suggested" (dashed) until a decision succeeds. Every fact shows its provenance.

## Deviations from the issue text

- **The decision body** is the contract's `NurseDecision`. It uses `action: "CONFIRM" | "OVERRIDE"`, `final_level` and `override_reason_code`, with free text in `override_note`, where the issue says `{action: "confirm", level, reason}`. The issue's autonomy default says the contract wins.
- **Contract additions for data the issue needs:**
  - age, sex, complaint and warnings on worklist rows;
  - NEWS2 total, subscores and band, warnings, and the ECG task on the triage view;
  - alert templates generated for TypeScript.

  All are optional, for M1-12 to fill.
- **An event refetches the whole worklist:** there is no single-item route, and the list is small.
- **The transcript is not shown:** no route exposes it, and StructuredFacts has no turns.
- **Staff layout:** the main column is wider (72 rem) so the seven-column worklist fits; the sign-in and triage pages keep narrower widths.
- **Arabic strings** for the new screens are machine-written (the Arabic UI is M2-01).
