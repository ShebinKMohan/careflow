## 2. A summary with an uncited sentence, an unknown id or a number not in its cited facts is dropped; the plain list is returned

There are 12 hand-written hallucinated replies (`fixtures/briefing/hallucinated.json`, chest-pain persona). Each is served by a scripted provider, and each gives `summary_status=dropped`, `summary=null` and the same sections as the plain briefing:

| Case | Drop reason |
|---|---|
| uncited sentence | sentence 2 cites no fact |
| unknown fact id | sentence 1 cites a fact that is not in the briefing |
| number not in cited facts ("Heart rate is 124 /min") | sentence 1 has a number that is not in its cited facts (124) |
| number from an uncited fact | … (104) |
| "consistent with a cardiac cause" | reads as a diagnosis or advice ('consistent with') |
| "likely cardiac" | … ('likely') |
| "Rule out a cardiac cause" | … ('rule out') |
| "should have a repeat ECG" | … ('should') |
| "angina" (not in the cited facts) | names a condition that its cited facts do not ('angina') |
| "amlodipine 5 mg" | has a number that is not in its cited facts (5) |
| 6 sentences | the model's reply did not validate twice (the draft allows 5) |
| not JSON | the model's reply did not validate twice |

The valid reply (2 sentences, citing 5 facts) is kept with `summary_status=ok`, and the briefing still validates against the contract.

**Recorded replies from the local model.** `scripts/with_llm.sh uv run python -m careflow_intake.briefing.record --persona all` recorded them into `<persona>.cassette.json`, with the outcomes in `<persona>.summary.json`. The replay test gets the same status, reasons and sentences.

- **First recording:** 2 of 7 passed. 3 replies were cut off at mlx_lm.server's default of 512 tokens, and 2 had more than 5 sentences. The check dropped all 5, as it should.
- **The fix:** `max_tokens` 1536, one-line JSON in the prompt, and the 5-sentence limit in the draft schema, so an over-long reply gets the one retry.
- **Second recording:** 7 of 7 pass the check. 3 used the retry.

## 8. The doctor route returns 403 for nurse-only tokens

`services/api/tests/test_briefing_route.py` (11 passed, Postgres up) covers:

- **Other roles:** `nurse`, `admin`, `kiosk_device`, `patient_session`, `board` and `integration` each get 403 as problem+json. No token gets 401.
- **Stored:** a briefing built by `BriefingService.make` is returned to the doctor and validates against the contract. Its row holds `summary_status=disabled`, `source_missing=0` and `document_status=skipped` ("the triage is not written back yet").
- **On demand:** with nothing stored, the route builds the briefing from the session's intake state (the `StateSource` port) and stores it. The second call is served from storage without loading the state again.
- **404:** another clinic's session; a session the nurse has not confirmed ("The nurse has not confirmed this session yet."); an unknown session; a session id that is not a UUID.
