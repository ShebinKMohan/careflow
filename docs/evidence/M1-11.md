## 1. An event added in a rolled-back transaction is never published

`test_an_event_in_a_rolled_back_transaction_is_never_published`:

- `add()` runs inside a transaction that then raises, so the transaction rolls back.
- The relay's pass sends 0.
- The stream has 0 entries and the outbox has no row.

## 2. 1,000 events, with the relay cancelled mid-run and restarted: delivered at least once, handled exactly once, zero lost

`test_1000_events_survive_a_relay_crash_and_restart_and_run_once`:

- 1,000 `token.called` events go in through the outbox (10 transactions over 2 clinics).
- A consumer group records each event it handles.
- The first relay crashes three times after `XADD` and before the commit, which re-publishes those batches. It is cancelled mid-run (after 300 or more rows are published and while some remain), and a second relay finishes.

```
1000 events: 3 relay crashes after XADD, first relay cancelled mid-run; 1301 stream entries, 1000 distinct, 1000 handled
1 passed in 3.67s
```

- The stream holds every event at least once: 1,301 entries, 1,000 distinct ids, equal to the outbox's ids. Nothing is lost.
- The side effect ran exactly once per event: 1,000 handled, and `processed_events` holds 500 rows per clinic.
- **Mutation check:** without the `processed_events` check, the handler runs on duplicates and this test fails.

## 3. `alert.raised` reaches a staff WebSocket client with p95 < 1 s over 50 runs

`test_an_alert_reaches_a_nurse_in_under_a_second_at_p95`:

- **Setup.** A real uvicorn server runs the app in-process, with its lifespan: the relay every 100 ms and the hub. A nurse connects with a ticket.
- **Each of the 50 runs** commits an `alert.raised` through the outbox and times it until the frame arrives.

```
alert.raised commit->nurse socket over 50 runs: p50 129 ms, p95 135 ms, max 151 ms   (first run)
alert.raised commit->nurse socket over 50 runs: p50 168 ms, p95 178 ms, max 180 ms   (later run)
```

The later run is slower because the relay then walked many more clinics: the test database keeps every clinic earlier tests made (ADR-026). Each frame is exactly `{id, type, timestamp, data}`.

## 4. A staff client from another clinic receives nothing; a patient socket never receives `alert.raised`

`test_another_clinic_hears_nothing_and_a_patient_never_hears_an_alert` publishes, in clinic A:

- `alert.raised` for session S;
- `token.called` for S;
- `token.called` for another session.

| Socket | Received |
|---|---|
| Clinic A's nurse | all three |
| Clinic B's nurse | nothing within 1 s |
| S's patient socket | only its own `token.called` |

**Mutation check:** with `alert.raised` added to the patient allowlist, this test fails.

## 5. Invalid payloads are rejected by `add()`; a reused ticket is rejected

- **`test_invalid_events_are_refused`:**
  - an unknown type raises `ValueError`;
  - another type's data model raises `ValidationError`;
  - an event for another clinic is refused by RLS (`DBAPIError`).

  No row is written in any of the three cases.
- **`test_a_ticket_works_once_and_only_for_its_channel`:**
  - a used ticket closes with **4401**, and so does a missing ticket;
  - a staff ticket on a session socket closes with 4403;
  - ticket requests: a board asking for a session channel gets 403; a patient asking for the staff channel gets 403; a patient asking for another session gets 403; a session channel without `session_id` gets 422; no token gets 401.

## Deviations from the issue text

- **The relay reads each clinic in its own RLS-scoped transaction** as `careflow_app`, not through a separate role that sees every clinic. Such a role needs `BYPASSRLS` from a superuser, which the migrations cannot grant and the init script adds only on an empty volume. ADR-026 records the upgrade path for many clinics.
- **Idempotency keys** are unique per clinic (`UNIQUE (clinic_id, idempotency_key)`), not globally, so a key in one clinic never swallows another clinic's event.
- **Nurses also receive** `patient.feels_worse` and `nurse.flag`: both contract events are addressed to nurses.
- **Frames carry the stream `id`**, for `?last_event_id=`. Heartbeats are application frames, `{"type": "heartbeat"}`.
- **Admin may request a ticket.** It was added to the contract's roles, since the issue gives admin every event.
- **`/v1/ws/*` is excluded from tracing,** so a ticket in a WebSocket URL never reaches a log.
- **`Event.type` accepts the internal types** (`INTERNAL_DATA_MODELS`) so they can go through the outbox; they never reach a socket.
