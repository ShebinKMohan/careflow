## Other checks in the test suite

- `FactKey` equals the set of leaf fact paths derived from the schema (55 paths), and includes every name other issues rely on (`chest_pain.present`, `vitals.diastolic_bp`, `complaint_category`, `child_danger.appears_ill_to_hcp`, `child_amber.cap_refill_3s_or_more`, ...).
- Unknown fields (on a fact or at the top level), a Fahrenheit unit on `vitals.temperature_c`, SpO2 101, ACVPU code `X` and naive date-times are rejected by both validators.
- Alert templates: every `RuleId` has `en` and `ar` lines and a `required_action`; every rule plus all qualifiers fits in 160 characters; templates contain no placeholders; the generated module matches the YAML; fixture alerts use the templates.

## Deviations from the issue text

- Code generation adds `--collapse-root-models --use-type-alias --strict-nullable --formatters ruff-format --custom-file-header-path` to the listed flags (all confirmed in `datamodel-codegen --help` for 0.83.0). Without them, ids and `SourceRef` would be RootModel wrappers (`fact.source.root.kind`; unhashable ids in lists) and defaulted lists would accept `null`. Generated files get a DO-NOT-EDIT header that disables pyright's `reportIncompatibleVariableOverride` for them only. Ruff skips `generated/`; CI regenerates and diffs instead.
- Shapes the issue left open are recorded in ADR-009: `CodeFact.value` is a `Coding`; patient demographics are facts; vitals have fixed UCUM units; `Alert.missing_inputs` uses `FactKey` paths (`vitals.respiratory_rate`); `NurseDecision.suggestion_id` is required but nullable (model failure).
- Extra helpers: `validators.check_transcript_spans`, `check_unique_fact_ids`, `check_structured_facts`, `check_suggestion_evidence`, `check_nurse_decision`; `alert_text.render_display_text` / `required_action_for`; `careflow_contracts.testing` (registry, validators, fixture loading) for other lanes' tests; `alert_templates.yaml` compiled to `generated/alert_templates.py`.
- `scripts/check_banned_deps.py` no longer crashes on an unparsable `pyproject.toml` (it reports it), and its LiteLLM-injection test handles packages with real dependencies.
- Fixtures follow the M0-05 personas (ages, sex, conditions, FHIR ids `persona-<id>`); the drowsy child is male (M0-05 leaves the sex open).
