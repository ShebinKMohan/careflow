## 1. `uv run pytest services/voice` passes

```
$ uv run pytest services/voice -q
854 passed, 2 skipped in 12.34s          (the 2 skipped are the live tests, without CAREFLOW_LIVE_VOICE=1)
```

The count includes the 798 copied agent tests that apply ([SOURCE.md](../../services/voice/SOURCE.md) lists the ones left out). The issue's three named checks:

- **WS protocol** (`test_kiosk_ws.py`, the real app with the real turn loop; only the models are fakes; the API is mocked by respx):
  - A bad start closes with **1008** (parametrised): a garbage token, an expired token, the wrong secret, a nurse token, another session's token, `sample_rate: 8000`, or a message that is not JSON. Audio before the start message, and no start within the timeout, close with 1008 too.
  - The fixture frames go through: `final` "I have chest pain since this morning." → `question` (the next question with its notice) → `tts_start` (24,000) → 28,800 bytes of TTS audio → `tts_end`.
    - The request was `POST /v1/sessions/ses_voice/turns` with `{"input_mode": "voice", "text": …, "language": "en"}` and `Authorization: Bearer <patient token>`.
- **`MlxWhisperSTT` with a fake transcribe** (`test_mlx_whisper_stt.py`, 11 tests):
  - one final event per turn, and silence never transcribed;
  - smart-turn holds an unfinished sentence to the hard cap and commits a finished one early;
  - two utterances make two turns;
  - clear errors when the extra or the local model is missing;
  - the exact `mlx_whisper.transcribe` arguments.
- **`/plivo/answer` returns 404 when the flag is off,** as do `/calls/outbound` and `/preview/turn`. With `VOICE_PLIVO_ENABLED=true` the route exists; the flag without `public_base_url` is refused.

**Also covered:**

- **Barge-in:** speech during the question sends `tts_end` with `interrupted: true` and becomes the next turn.
- **Errors keep the session open:** 401, 404, 409 and 503 from the API, an unreachable API, bad frames and bad messages each become an `error` message.
- **Replies:** a done reply (`question: null, done: true`); the `next_prompt` fallbacks.
- **Turns client:** the contract request body, and its error codes.
- **Tokens:** one issued by `careflow_api.security.create_access_token` is accepted; the algorithm and required claims equal the API's.
- **Speech config:** `providers.yaml` gives mlx-whisper and Kokoro, and the environment still wins.
- **Readiness:** `/readyz` lists missing model files.
- **Latency:** `/latency/summary` has kiosk p50 and p95.
- **Kokoro:** native 24 kHz output.

## Deviations from the issue text

- **Turn body.** The voice service posts the contract's `{input_mode: "voice", text, language}`, which the issue calls `{text, source: "voice"}` (as in M1-13).
- **Protocol additions:**
  - `question` also carries the API's `next_question` and `done`, so the kiosk shows the tap answers for its key;
  - `tts_end` carries `interrupted`;
  - the start message may carry `language` (`en` only in M1).
- **`VoiceClient` changed shape:** `start(session, events)` with transcript, question and error events. The voice service posts spoken answers itself, so the kiosk must not post them.
- **The phone channel's control routes** (`/calls/*`, `/preview/*`) are gated with `/plivo/*`, since they drive Plivo calls and the agent's LLM.
- **The whisper model is fetched by the download script too,** into `models/whisper-large-v3-turbo/`, so mlx-whisper never downloads on first use.
- **Copied tests of `dev/` scripts are left out,** because `dev/` is not copied. `test_packaging.py` keeps only its dependency check.
- **Dependencies dropped:** `google-genai` and `sherpa-onnx` (their providers stay in the code, unused). The agent's version ranges were moved to the workspace's (Redis 8, websockets 16).
- **Legacy files with pyright errors are excluded** from pyright one by one (allowed by the issue).
- **The live tests need `CAREFLOW_LIVE_VOICE=1`,** like the LLM live tests need `CAREFLOW_LIVE_LLM=1`.
- **The browser check's voice service uses port 8095** (see §4).
