## Other checks

- Each infection trigger raises at NEWS2 ≥5: suspected, fever, rigors, measured temperature 38.1 or 36.0, productive cough, dysuria, wound redness or discharge. Nothing raises for "no"/"unknown" answers, a temperature of 38.0 or 36.1, a patient-stated temperature, or an unrelated symptom.
- NEWS2 4 with a suspected infection raises no alert but still asks the nurse for the missing inputs. NEWS2 exactly 5 raises.
- Children under 16: `news2` is `None`, `news2_not_applicable` = "NEWS2 not applicable under 16", and no SEPSIS_NEWS2.
- An Arabic session gets the Arabic template and qualifier. Alert ids are stable per session and rule. A naive `now` raises `ValueError`.
- Engine contract with stand-in rules: alerts are deduped by rule id (first wins) and sorted critical before high; needed facts are deduped by key and audience.
- `merge_vitals`: a nurse value wins even over a newer device reading; otherwise the newer reading wins.
- `/v1/admin/status` now reports `ruleset_version` `2026.1.0` (`careflow_api.routers.admin.ruleset_version()`).

## Deviations from the issue text

- **Under 16:** `score_news2` returns `None`, and the reason is carried in `RulesResult.news2_not_applicable`, because `None` itself cannot hold a reason.
- **Nurse over device:** the contract keeps one current fact per vitals path, so the rule "if a device value and a nurse value both exist, use the nurse value" is implemented as `merge_vitals()`, which callers apply before `evaluate()`.
- **Needed facts:** a suspected infection lists every missing NEWS2 input for the nurse, including when NEWS2 is below 5. At the kiosk these are exactly the four named in the issue.
- **Test builders** live in `careflow_rules.testing`, following `careflow_contracts.testing`: pytest's importlib mode cannot import a sibling helper module.
