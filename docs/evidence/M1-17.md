# M1-17: the doctor briefing, the public board and the admin status, verified

Status: every acceptance criterion met on 27 September 2026 (mapping at the end). The screens
were merged earlier (PR #25); this change adds the deferred verification and fixes what it
found. The PR, its CI and the merge commit are in the Linear SHE-313 done report.

**These are mock-backed checks by design.** The component tests stub the API client and the
Playwright tests stub HTTP with `page.route()`, both from synthetic fixtures derived from the
contract's own examples (`apps/staff/tests/fixtures/api/`). The same screens against the real
API, a persisted briefing and live queue updates are the journeys' proof (SHE-315 [M1-19],
SHE-311 [M2-12]); a passing mock is not that proof. Research prototype; synthetic data only.

## What changed

- **The public board could stay stale silently.** A failed poll kept the last answer on screen
  with nothing to say so, so a board could keep "calling" numbers long after the API went away.
  It now shows "Connection lost. This board may be out of date (last updated HH:MM)." (clinic
  time zone) while keeping the last numbers, and the next answer replaces them and clears it.
- **The admin status now says what actually runs** (API): a local model is available only when
  its server answers `/models` (probed once per server, 1 s); a missing urgency model reads
  "none: no suggestion" and one trained on the synthetic fixture is "degraded",
  "trained on the synthetic fixture, not KTAS (NOT A RESULT)".
- **Speech and FHIR write-back health were missing** from the admin status (issue step 6). It
  now lists `speech:stt` and `speech:tts` per language from `config/providers.yaml`, "ok" only
  when CareFlow's voice service answers. On this machine port 8090 is taken by another copy of
  the voice agent that also answers `/healthz` `{"status":"ok"}`, so the CareFlow voice service
  now names itself (`"service": "careflow-voice"`) and anything else counts as down. The
  `fhir-writeback` row shows the bus consumer's state (ADR-043) and this clinic's failed
  write-backs. Tests: `services/api/tests/test_admin_honesty.py` (3) and the flow test's admin
  check on the isolated stack (consumer consuming, 0 failed write-backs).
- `@axe-core/playwright` 4.13.0 is pinned in the pnpm catalog (staff devDependency).
